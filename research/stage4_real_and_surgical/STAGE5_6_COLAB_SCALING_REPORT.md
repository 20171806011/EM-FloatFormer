## 执行摘要（Executive Summary）

本次 Colab Pro+ A100-80GB 收官实验一次性产出了 Stage 4（`Qwen/Qwen3.5-4B` 真实 SDR 与 `W2 Lie+Schur Soup`）、Stage 5（`CN-SFT` `4B BF16 -> 9B BF16 -> 27B W4 Mixed-NF4` 跨尺度零样本迁移）与 Stage 6（`m5-stage6-blind-v1` 16 态主动实验设计 EIG）共 6 份全量结果 JSON。结合源码审计、统计配对检验及与 `codex-cli` 的两轮交叉质询，核心实证结论可收敛为五条硬事实：

1. **Stage 5 `CN-SFT` 编译物理推理回路在 4B / 9B / 27B Mixed-NF4 上实现无损、零纯净干扰的跨尺度移植，但主要功劳来自 Regime-2 编译电路而非冻结 LLM 原生发现 RF DSP**：
   - `4B BF16`、`9B BF16` 与严格满足 `W4 定理 2` 红线的 `27B Mixed-NF4`（仅 192 个 SwiGLU MLP 投影量化为 NF4，305 个非 MLP 线性层维持 BF16，`forbidden_quantized=[]`）全部因第 9 / 17 层分布外线性相位探针得负 $R^2$（`-1.11656` / `-0.86881` / `-0.92142`）统一路由至 **Regime 2**，并均以 `PureKL = 0.0` 通过零干扰验证。
   - 在未见真实硬件录音 `cttc_unseen_holdout_f708_snr10` 上，三个尺度（包含完全跳过 U1 训练的 `27B U0`）均达成完全一致的 **`83.75% Q1 / 86.25% 两导频 Q2`** 准确率（Q2 NLL `0.4383–0.4624`）。对照无宿主 CPU 物理接收机（[`real_sdr_cpu_physical_report.json`](./results/real_sdr_cpu_physical_report.json) 同集已达 `83.75% / 86.25%, NLL 0.4085`）与 `U2` 消融证据，`Stage 5` 严格证明的是“**Regime-2 物理回路与规范化/去偏框架可在 4B–27B 冻结宿主上无损移植**”，而非冻结语言模型主干独立学会相位物理推理。
2. **4B 历史基线 Real-SDR 与 `W2 Lie+Schur Soup` 实证证伪（[`stage4_real_sdr_4b_results.json`](./results/stage4_real_sdr_4b_results.json)）**：
   - 仅经 Phase A 训练的纯神经宿主 `equivariant_host_pure` 陷入 `Pluto` 典范坐标捷径（无论有/无导频 `Pluto Q2` 均为 `95.71%`，而域内 `CTTC Q2_two` 停滞在 `24.92%`，`f708 Q2_two` 为 `27.50%`，相对零基线配对检验 $p = 0.5446$）。
   - `W2 Lie+Schur Soup` 虽然完美保持全部代数不变量（`b_align_diff = 0.0`、Cayley 酉性缺陷 `1.1888e-7`、float64 Schur 重构误差 `4.7095e-19`、`PureKL = 0.0`），但因缺失 Fisher 查询门控、使用早期 4 句 K-FAC 及专家域内失配，在 `f708 Q2_two` 上产生严重过度自信误判（NLL `3.6366` vs `LEMMO 因子平均` `1.3918`，配对差 `+2.2448 nats`, $p = 2.27\times 10^{-5}$），同时 `MixKL` 升至 `0.0749`。`LEMMO` 因全时激活则违反 `PureKL = 0`（`pure_max_logit_diff = 0.21875–0.484375`）。
3. **Stage 6 主动实验设计出现 `4B (4-bit > 16-bit)` 与 `9B (16-bit > 4-bit)` 镜像倒挂**：
   - `M5` 物理基准（[`verify_m5.py`](../stage4_math_and_design/M5/verify_m5.py)）达成 `98.20%`（NLL `0.04823`）。在冻结宿主上，**`4B` 呈现 `S17 4-bit (78.56%, gate=True)` 大幅领先 `C16 16-bit (60.64%, gate=False)`**（配对差 `-17.91 pp`, $p = 1.22\times 10^{-209}$）；而 **`9B` 完全反转，`C16 16-bit (78.99%, gate=True)` 碾压 `S17 4-bit (61.39%, gate=False)`**（配对差 `+17.59 pp`, $p = 1.76\times 10^{-210}$）。
   - 即使按 `M5` 规范改用**共享揭示动作**（`random_window` / `nearest_window` / 固定窗口 `constant_0..3`），该宿主×位宽符号反转依然稳固存在（`random_window`: 4B `-4.48 pp`、9B `+7.83 pp`；`nearest_window`: 4B `-3.87 pp`、9B `+9.09 pp`），只是 `max_EIG` 自适应挑选将其放大至 `±18 pp`。Codex 数值积分上界证明，约 `79%` 的赢家模型确实突破了 `62.06% (jump)` / `61.93% (cfo)` 均匀模态贝叶斯天花板，真实利用旧包信息进行窗口选择；但因 `S17` 特征严格嵌套于 `C16` 且每臂仅跑单一随身种子（`202642` vs `202635`），当前数据尚不足以把 `±18 pp` 倒挂唯一归因于物理表示容量而非单种子优化轨迹分岔。
4. **`27B Mixed-NF4` 在 Stage 6 完全退化至“丢弃旧包证据的均匀先验参考”（`~51%`, `NLL ≈ 0.6922`）**：
   - `27B` 全部三臂（`C16 51.05%`、`4-bit 51.28%`、`CN-SFT U0 51.08%`）均未通过 Stage 6 检验，所选窗口 `expected_eig` 比 `9B C16` 萎缩 **67×–1,460×**。Codex 确定的 M5 均匀先验 `q(r,g)=1/16` 种群基准给出 `50.82%` 准确率、`0.69246` NLL 及 `CFO` 窗口 2 预期 EIG `0.002055 nat`，与实测 `27B C16`（`51.05%` / `0.69224` / `0.002036 nat`）高度吻合。由于 `27B` 同时耦合了 64 层深混合结构、8-token `* 0.05` 软前缀、`Mixed-NF4` 反向传播与 `grad_ckpt=True`（训练期 `lm.train()`），当前仅能将其定性为“该混合量化与检查点训练配置下 240 步单种子读取头失效”。
5. **跨任务负迁移（`-3.12 pp` 至 `-18.99 pp`）与两条代码观测缺陷**：
   - 将在 Stage 4 C4 四分类序列似然任务上训练的适配器（`surgical` / `lemmo` / `cn_sft_u1`）无载波直接挂载至 Stage 6 16 态末位隐向量读取任务时，均导致同格式 `C16` 性能显著回退（9B `-18.99 pp`、4B `-3.12 pp` 至 `-5.87 pp`），而无 LoRA 且跳过 `_schur_last` 的 `27B U0` 仅差 `+0.03 pp`。
   - 公开披露 [`colab_stage6_scaling.py`](./colab_stage6_scaling.py) 中的两处日志缺陷：(i) 冻结后调用 `requires_grad` 过滤的 `param_count()` 使 `4B surgical/lemmo/U1` 与 `9B U1` 的 `cnsft_adapter_params` 均被误记为 `0`；(ii) 4B Stage 6 `CN-SFT` 后验 KL 审计因未传入 `frozen_refs` 触发 `_attach_hooks` 丢失只读 Fisher 探针，产生 `MixKL = 33.29` 的无效数值，而同环境有效的 4B Stage 4 Colab 审计显示 `MixKL mean = 0.0010670`（略高于 Modal 上 `0.0009164` 的 `1e-3` 及格线）。

- **机制解读（Codex 共识）**：
  1. 三个尺度均在探针层给出负 `r2_ood_phase_slots`，触发确定性路由至 **Regime 2**，为后续全部任务提供统一的 FP32 `ShadowGDN` + 谐波乘积 MLP + 宿主数字框对齐（`b_align_fixed_err = 0.0`）通路。
  2. Fisher QGate `scale` 随尺度呈 `7.6575 -> 4.3974 -> 1.7211` 单调下降，并非表示“宿主推理变强”，而是 [`cn_sft_probe.py`](./cn_sft_probe.py) 直接按标定投影间隔的倒数设置 `scale`（正负边界间隔从 `1.567` 升至 `2.729` 再到 `6.972`）。
  3. **后缀模板校准与 `27B` 的 `g_eff=1.0`**：4B `U0` `pre_max_abs` 最高为 `0.40824`（tid 0）-> 校准后压至 `0.07719`（`g_eff[0]=1.3725`）；9B `U0` `pre_max_abs` 高达 `1.476` -> 校准后压至 `0.08493`（`g_eff={1.2071, 1.0, 1.0258, 1.0909, 0.8894}`）；而 **27B `U0` 五个任务的 `pre_max_abs` 全在 `0.00118–0.02247` 之间**。因低于 `0.10` 校准死区阈值，[`calibrate_template_suffix_bias`](./cn_sft_probe.py) 直接触发“零修正分支”输出默认 `g_eff = 1.0`，说明 `27B` 原生候选词模板残余偏置在动态去偏后本身极小，而非优化收敛出的增益 `1.0`。

### 4.2 现象一：4B / 9B 位宽倒挂与“模态选择能力”验证
1. **协议细则修正与反转真伪甄别**：`M5` 协议要求比较不同位宽时采用相同的揭示动作，而现行主表比较的是各模型自主 `max_EIG` 所选窗口的端到端结果。尽管如此，我们从各 JSON 的共享控制策略中抽取出同一动作对决：**在 `random_window`（4B `-4.48 pp`, 9B `+7.83 pp`）、`nearest_window`（4B `-3.87 pp`, 9B `+9.09 pp`）以及全部四个 `constant_0..3`（4B `-6.07` 到 `-1.63 pp`；9B `+5.18` 到 `+10.14 pp`）上，4B/9B 符号反转无一例外地稳定成立**，`max_EIG` 挑选只是把约 `4–9 pp` 的底层读取器质量差放大到了 `±18 pp`。
2. **`79%` 赢家确实恢复了模态局部化信息**：对 M5 高斯模型进行精确数值积分核验表明，即使给阅读器提供**完美 4 相位规范 $g$** 但完全不提供窗口模态 $r$（均匀模态），贝叶斯最优准确率上界在 `jump_interval` 上仅为 `62.06%`，在 `cfo_alias` 上仅为 `61.79–61.93%`（Pooled `66.20%`, NLL `0.56389`）。而 **`4B S17`（`77.88% / 76.51%`）与 `9B C16`（`76.56% / 77.47%`）显著突破该上界**，倒推其真实匹配窗口选择率 $P(a=r)$ 至少达到 `~55%–58%`（远高于均匀随机 `25%`）。而仅知道模态却丢失相位（`q(r,g)=q(r,g+2)`）的理论天花板为 `51.93%`（`jump/fade` 上严格等于 `50.00%`），说明 `60%` 较弱组仍捕获了一定比例的符号化相位信息，只是模态定位和后验置信度显著不足。
3. **尚未排他的两类成因假说**：代码级检查（[`equi_connector.py`](./equi_connector.py) 与 [`real_sdr_and_stage6_gpu.py`](./real_sdr_and_stage6_gpu.py)）表明，`S17`（仅用高 4 位 `word >> 12`，将连续 `tail` 6 维/窗全置零）**严格嵌套**在 `C16` 参数空间内。两臂在同一宿主下差异源于：(i) `30` 个额外连续尾比特输入通道改写了特征协方差及初始软 token；(ii) `seed + bits + len(mname)` 使 `C16 (202642)` 与 `S17 (202635)` 在 240 步（前 120 步消耗 `77.46%` 调度学习率总和，三家族均衡各 80 步）下采样了不同的初始化和 batch 顺序。仅靠每个条件单一轨迹无法区分“4B 优化未跳出早期局部平台 vs 尾比特梯度干扰小宿主”。

### 4.3 现象二：27B Mixed-NF4 退化至均匀先验参考（`~51%`）
Codex 在 M5 种群上算出的 **“全丢弃旧包（$q(s)=1/16$）”理论基准为 `50.82%` 准确率、`0.69246` NLL、`CFO 窗口 2 expected_eig = 0.002055 nat`**。这与 `27B C16` 实测（**`51.05%`、`0.69224`、`0.002036 nat`**）几乎精确重合，构成强力的行为指纹。然而由于 `Stage 6 on 27B` 同时引入了 4 个变量，当前实验无法单独切割归因：

## 五、代码审计取证与实验记录透明度披露

为保证学术严谨，本节明确列出代码排查确认的两处 [`colab_stage6_scaling.py`](./colab_stage6_scaling.py) / [`real_sdr_and_stage6_gpu.py`](./real_sdr_and_stage6_gpu.py) 观测缺陷，以及跨平台运行时数值边界漂移：

1. **参数计数冻结后归零（广泛存在于已训练适配器挂载臂）**：
   - `CNSFTHostAdapter.param_count()`、[`SurgicalHostAdapter`](./surgical_adapter.py) 及 `UnconstrainedLoRAAdapter` 均通过 `if p.requires_grad` 统计可训练参数。然而评测器在读取检查点后立即执行 `adapter.requires_grad_(False)` 并随后统计参数量，导致所有挂载历史微调适配器的 Stage 6 记录中 `cnsft_adapter_params` 或 `cumulative_params` 遗漏了继承参数。实际口径分拆如下：

   | Stage 6 模型臂 | Stage 6 可训练头参数 | 继承的已训练适配器参数（不含 Stage 4 连接器） | 实际合计已学习参数 (`Stage6 + Stage4`) |
   |---|---:|---:|---:|
   | `4B host_surgical_c16` | `617,760` | `1,237,537` | **`1,855,297`** |
   | `4B host_lemmo_c16` | `617,760` | `1,154,048` | **`1,771,808`** |
   | `4B host_cnsft_c16 (U1)` | `617,760` | `1,178,439` | **`1,796,199`** |
   | `9B host_cnsft_c16 (U1)` | `917,280` | `1,531,719` | **`2,448,999`** |
   | `27B host_cnsft_c16 (U0)` | `1,116,960` | `0`（仅固定缓冲区校准参数） | **`1,116,960`** |

2. **4B Stage 6 `CN-SFT` 误测为 `MixKL=33.29` 的无效审计 + Colab 实网边界漂移**：
   - [`stage6_active_eig_4b_cnsft_results.json`](./results/stage6_active_eig_4b_cnsft_results.json) 末尾记录了 `pure_kl_mean=0.0` 但 `mix_kl_mean=33.2875` / `mix_kl_max=63.5914`。代码取证证实该审计在 Stage 6 **预测完成之后**才运行，对 `57.53%` 精度没有任何因果影响；其数值异常源自 [`colab_stage6_scaling.py`](./colab_stage6_scaling.py) 未传入预计算 `frozen_refs`，致使 [`phaseB_surgical.py`](./phaseB_surgical.py) 先调用 `cn_ad.remove()` 清除了独立挂载的只读 Fisher 探针，随后重挂默认钩子时因 `stop_layer=-1` 跳过 `_stop_hook`，导致第 0 层清空缓存判别 verdict 后在混合提示词上无门控注入（与 Modal `U3_gate_off_audit` 的 `38.26 / 65.19` 同理但不完全等价）。因此 **4B Stage 6 预期门控下的 `MixKL` 应标记为“审计脚本缺漏（无效）”**。
   - 同时须诚实保留有效审计的真实差距：在同环境 Colab A100 上使用正确 `audit_cn_sft_pure_and_mix_kl` 测得的 [`stage4_real_sdr_4b_cnsft_results.json`](./results/stage4_real_sdr_4b_cnsft_results.json) 返回 `PureKL = 0.0`，**`MixKL mean/max = 0.0010670 / 0.0031038`**，略高于 `1e-3` 及格阈值（`passes_mix_kl_1e3 = False`），而 Modal 同权重（`torch`/CUDA 较旧环境）测得 `0.0009164 / 0.0018809`（`True`），Colab 9B Stage 6 正常传入 `frozen_refs` 后也顺利通过（`0.0008498 / 0.0027347`, `True`）。不能用 Stage 4 数值替代 Stage 6 缺失审计，也必须如实注明 4B Colab 与 Modal 在 `1e-3` 红线边缘的跨环境漂移。

## 六、Codex-CLI 双轮讨论精华与零浪费 Stage 6b 验证矩阵

在与 `OpenAI Codex v0.166.0` (`gpt-6.2-astra`, `reasoning effort: ultra`) 进行的两轮只读代码与统计交叉核验中（原始逐字稿仅留存本地隐私工作目录，不纳入 Git 公开仓库），双方对齐了论文可稳妥主张的三大核心贡献（**`CN-SFT` 物理推理回路在 4B / 9B / W4-NF4 27B 上的 `PureKL=0` 零样本移植与 `86.25% f708` 泛化**、**`9B C16 (78.99%)` 与 `4B S17 (78.56%)` 利用旧包选窗突破均匀模态上界**、**`W2` 线性均值重构与非线性读取断层的实证反例**），并收敛出严格限缩在 **CPU 前置 + 单轮 20 分钟 Colab A100 预算（`$0` Modal 支出）**内的最小可证伪 **Stage 6b** 诊断矩阵：

| 优先级 | 实验设计 | 关键控制与观测字段 | 可证伪判据 |
|---|---|---|---|
| **Priority 0 (CPU, `$0`)** | 同包等权前向一致性检验 | 给 `C16` 编码器喂入与 `S17` 完全相同的原始 16-bit 字，仅将每窗 6 维连续尾特征清零、共享同一 `S17` 头部权重并冻结尾列屏蔽掩码。遍历全部 65,536 个单字及典型 5 窗批。 | 检出任何特征/软 token 差异即定位编码器实现分歧；若严格对齐，则确立 `S17 ⊂ C16` 等价嵌入。 |
| **Priority 1 (Colab 27B 无训练探针)** | 27B 模式/检查点一致性 + 分层线性探针 | (1) 固定相同 NF4 宿主、头部、批次与随机种子，比较 `eval/off -> train/off -> train/on(grad_ckpt)` 三态下 logits 与对 8 软 token 的输入梯度方向/范数；(2) 在 `eval` 态缓存第 16、32、48、64 层的末位软 token 与末位文本 token 隐向量，CPU 拟合正则化模态 $r$ 与相位 $g$ 线性探针。 | 若 `train/on` 相对 `eval` 梯度方向畸变，直接坐实 `grad_ckpt`/后端交互缺陷；若第 64 层文本末位探针失败而中层或软 token 末位成功，则局部化为深度前缀到末位读出衰减；在得出该定位前不启动昂贵的 27B 全 BF16 训练。 |
| **Priority 2 (4B & 9B 四组交叉种子复现)** | 补全交叉种子单元 (`~15 分钟`) | 分别在 **4B 与 9B** 补跑缺失的两个种子交叉点：**`C16 @ seed 202635`** 与 **`S17 @ seed 202642`**（归档已含 `S17 @ 202635` 与 `C16 @ 202642`），显式统一初始化与采样顺序、禁用旧缓存，记录第 `0, 40, 80, 160, 240` 步诊断集的模态 KL、条件相位 KL、$P(a=r)$ 与共享动作评分。 | 若胜负随种子走（`202635` 总是赢），则推翻“位宽×尺度”解释；若两种子下仍保持“4B 偏 S17 / 9B 偏 C16”，则实锤宿主与位宽的真实交互。 |
| **Priority 3 (9B 适配器负迁移定性)** | 固定赢家头 + 适配器开关对照 | 直接复用 `Priority 2` 的 `9B C16` 头部，在完全相同的输入批次上比较“无适配器 vs 全零更新挂载 vs 正常 Stage-4 `U1` 挂载 (`carrier=None`)”的残差变化、隐状态 KL 与输入梯度，外加一组同源 `seed 202641` 无挂载对照拟合。 | 立刻分离“即时前向特征破坏”与“训练早期梯度轨迹偏移”。 |
