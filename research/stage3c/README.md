# Stage 3C：上 GPU 前，哪些数学问题已经解决？

**结论。** 在原始 C4 工况、已知频偏、固定 s17 的 8 比特缓存及无导频条件下，独立统计检验支持已发布的两张表在全部缓存状态上都选中了贝叶斯最优类别。把这两张表作为 Q1/Q3 的判决基准。下一笔算力应优先用于检验冻结宿主能否使用有符号相位信息和新证据。这项结论针对指定模拟器的 top-1 判决；任意工况的概率校准、Q2 的最优类别、GPU 宿主收益和真实录制仍需分别评估。

## 一轮正式实验的执行决定

1. **确定一个主问题。** 冻结 Qwen3.5-4B 和 s17，比较两个等预算连接层。两臂读取相同缓存、文字、训练波形和非零正负频偏；相位臂额外取由同一公开参数算出的各时刻正余弦，对照臂同尺寸槽填零。时刻、扩散和 SNR 等其他信息对等，不额外泄露漂移实现或标签。保持候选打分器、温度校准程序、监督目标、初始化配对和训练步数一致。建议主对比使用硬物理标签，暂把新老师用作诊断；训练时加入老师概率会改变所检验的干预。
2. **锁定检验范围。** 主工况为 Q3 重发、2 dB、σ=0.1、h=ℓ=2、|ω|=0.40、总角度绝对值 1.60，两种符号均测。在已发布方案的非零训练支持上训练；用 2×2 工况分别检查频率和累计转角的内插/外推。改变时长也会改变扩散，不能从跨工况原始准确率差单独归因给角度。给 ±0.40 单独计算匹配的直接读出/概率参考；旧 +0.35 查表固定为历史锚点。历史 Ministral 的冻结权重可在同一批输入上做符号交换探针；评估跨宿主的训练干预复现时需要匹配训练，而非把两个历史分数相减。
3. **冻结方案再做正式训练。** 先用开发数据跑双方的 tokenizer、完整四候选似然、梯度、数值精度、缓存表索引及列出的中文选项。正式训练用 3 个预先登记、两臂配对的连接层种子；这里的一轮包含这些重复。冻结参数、种子、统计门槛及软件版本，再开启独立盲测。在 E 组规划假设下，主工况 8,256 条母波形。每个已冻结模型/种子/臂对两个符号的 Q3 只需打分最多 512 个缓存输入，然后按母波形和旋转索引取回；这些仍是 8,256 条源波形，不是 512 条训练数据，也不是数万条独立模型调用。Q2 带连续新导频的评测另计成本。
4. **区分实用改善、物理解释与系统行为。** 对主对比同时检查正确率增益和负对数似然降低。E 方案中的实用门槛是各自配对区间下端超过 2 个百分点与 0.02 nats。只满足一项则分别报告。用 F 组符号探针检查概率移动是否同物理方向一致。用 G 组对同一套已枚举输出做对称平均，可独立检验强制对称的系统收益；它与宿主原始行为分列。最后用 Q2 的无关、重复和新测量三臂检验修订答案。一个预训练检查点及三个固定连接层种子支持的结论有相应范围。

**待真实运行的部分。** 本阶段产物是数学推导、可复用的 Q2 读出核、确定性缓存包装器、样本量计算、宿主预测分析器及 CPU 证据。Ministral 修正中文题面的复验、Qwen 连接层训练和独立真实采集测试尚无本轮实测成绩。若目标只是跑出一个高分，数学不能替代宿主训练；这些结果把一次正式运行能回答的问题固定下来，让差、平、好三种结果都能解释。

python -B research/stage3c/verify.py --repo .
