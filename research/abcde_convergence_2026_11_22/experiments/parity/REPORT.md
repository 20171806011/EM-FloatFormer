# A/B 合并校验：实际 Python 修正与独立参考

纯 Python 接收机把整行边际、目标局部原始密度和分支内比特概率分开，使用双向 HMM 计算目标行权重。它在 A 的 21 个离散观测上与 49,280 个完整联合赋值的独立整数枚举逐候选、逐位一致。156 位、312 个候选×位，原及修正硬判全部相符。修正 P(1) 的最大绝对误差 3.34e-16，原读出 5.56e-16。A 的离散参考没有发送真值。对列出的 156 个条目等权，在各自精确条件分布下计算期望比特对数损失，原读出为 0.68092546、修正为 0.68070157 nats。这不是实测 BER，也没有按不同观测的产生概率重加权。

**同一个 16-QAM 样本。** 与 A 的 `ab_fixture.json` 比较前，脚本先断言 IQ、H、初始分布、转移及目标索引完全相同。六个 RE 中目标为 (0,1)，y=−0.88+2.63i。冻结局部方差 1.07675556、重估后 0.12。三种方案的局部 log m、分支内四个概率、门权、最终有效权重、最终概率、硬判均已交叉核对。两种温度共 152 项标量比较，另核对各硬判，最大 P(1) 误差 1.95e−15、门权 1.0e−15、局部 log m 3.56e−15；详见 oracle_result.json 和 raw.json.gz。A 自身的独立校验另有 196 项，二者不要相加作为独立样本数。

冻结其它参数。若目标局部边际为 m，原读出对目标的有效因子为 m^(1+1/τ)，删除显式项后再乘目标联合核为 m。完整权重乘归一化分支为 m^(1/τ)。最后两种在 τ=1 等价；τ=6 的非目标发射也受温标影响，属于经验加权。数据依赖的方差会随目标改变。上述恒等式是固定拟合量下的计算关系；留一重估是额外干预，不保证改善 BER 或 NLL。“严格”在这个简化模型中指从所有估计/门控途径排除目标；允许预测最后使用目标观测。

**带标签配对。** 冻结的合成输入见 fixture.json。12 个母帧，各 2 行×3 载波、每符号 4 bit；每帧的两种工况共享信道、发送符号和热噪声。各母帧依次在固定循环位置加幅度 2.8 的单点脉冲，或保持原热噪声。全网格每个 RE 逐一作目标，全部方案使用同一输入。两状态候选 H=[1,0.59+0.53i]、初始概率 [0.54,0.46]、stay=0.82、噪底=0.12，缩小模型沿用 B 样本。真实仓库 Dev 配置是 τ=6、stay=0.8；本实验只在小模型上切换温度，未改变转移。每工况 288 个 bit，合并 576 个 bit-condition 实例；独立母帧仍只有 12 个。无标签的 A/B 固定示例不进入分母。

输出 P(1) 和对数损失均在最终 LLR 温度校准之前；NLL=-mean(log p(true bit))，用 log-sum-exp 计算。救回是同一发射位从错到对，新增错误是从对到错。metrics.json 另给“严格重估相对仅删显式”的全部配对及分母。τ=6 合计两次显式翻转彼此抵消，平均 BER 相同仍有救回和新增错误。在局部强干扰时，重估可能排除识别异常所需的样本，造成很小的目标方差和过度自信；这是合成现象，不能代替硬件历史回放或盲测证据。

**运行环境。** 实际以 Skulpt 1.3.0（Python 3 模式）编译并执行了 parity.py 的接收机、样本驱动和统计函数，未把 JS 数值实现冒称为 Python。运行时编译标识等于 [Skulpt 1.3.0 发布源码](https://github.com/skulpt/skulpt/tree/6c99c2196851bb29f0e503afccb01804f089cb60)。[发行仓库固定提交](https://github.com/skulpt/skulpt-dist/tree/1473759236009587a04bd9875c7afd812d9f02d2) 的 JS 与标准库 git blob SHA 已重算，分别为 86e34f3d2d1e6a8a356f36d0c17aa3a71520e600、0c0a78ad6417c381842f46149c571614f39cfb31。没有运行 CPython/NumPy 原版端到端；pinned_adapter.py 提供后续同输入桥接。独立 V8 参考在 16-QAM 上用概率域枚举所有四条状态路径，对非目标符号独立求和；共核对 3,480 个比特输出、6,960 个候选×位，最大 P(1) 误差 6.56e−15，所有硬判一致。τ≠1 时，验证的是温度化公式一致性。三种方案按相同目标单位从头拟合并读出，先预热，各目标轮换执行顺序。秒数为各次 Python 调用的观测墙钟之和，含估噪、局部度量、HMM、读出，排除校验、文件 I/O 及 JSON 序列化。此解释器耗时不能外推到原版 NumPy 的实时性能。

## 重跑

以 Python 3 和 Node 18+ 运行，无外部 Python 包。将 A 的两个参考文件路径代入。默认输入与本记录相同。raw.json.gz.b64 以可移植 base64 包含此次实跑的 gzip 逐目标/候选轨迹，oracle.cjs 可直接读取该文件，压缩包内唯一 JSON 含各工况、温度、三个模式的局部方差和 log m、分支内四位概率、门权和有效权重、log 概率、最终硬判及汇总耗时。

~~~sh
python parity.py --a-reference /path/to/A/reference.json --out reproduced
node oracle.cjs fixture.json reproduced/raw.json.gz /path/to/A/reference.json /path/to/A/ab_fixture.json
node oracle.cjs fixture.json raw.json.gz.b64 /path/to/A/reference.json /path/to/A/ab_fixture.json
~~~

可选的原版接线需要 B/audit.py、固定 OFDM 提交源码和 NumPy、SciPy、PyTorch。单个目标，无训练和数据下载。调用后断言上述三个门控模式的实际原版局部边际、权重、分支和四位输出与本 Python 读出一致。

~~~sh
python pinned_adapter.py --audit /path/to/B/audit.py --ofdm /path/to/pinned/ofdm   --target 7 45 --tau 6 --stay .8
~~~
