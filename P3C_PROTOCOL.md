# EM-FloatFormer P3-C — CPU BF16/FP16 real-operator precision audit

**2026-11-15 · Frozen exploratory protocol, to be committed to GitHub BEFORE held-out evaluation.**

## Research question and precise limitations

Assess the numeric fidelity, bit decisions and latency of actual **CPU PyTorch BF16/FP16 autocast of learned real Conv1d operators** and separately **BF16/FP16 complex IQ component storage quantization**, compared with FP32. This is synthetic receive-only civilian 32-tone QPSK/OFDM. There is no radar, emitting hardware, active radio interference, or transmitter control. Existing P2-E/P3-A/P3-A2/P3-B reports and trained weights are immutable.

**Hardware limitation found BEFORE tests:** PyTorch 2.10 CPU supports `torch.autocast('cpu', dtype=torch.float16)` and `torch.bfloat16` for Conv1d, but `torch.fft.fft`/`ifft` of Half or BFloat16 on this CPU raise `RuntimeError: Unsupported dtype`. Therefore (a) FFT, complex multiplications, division, normalization, noise metadata remain FP32/complex64, (b) learned real Conv1d kernels execute under genuine BF16 or FP16 autocast, (c) final model logits may be FP32 because an FP32 skip path is added. No assertion of all-FP16, all-BF16 complex FFT execution or full half-precision OFDM receiver is allowed. Explicitly log which kernels actually run in lower precision and which do not. No use of an imaginary GPU.

## Frozen evaluated checkpoints, distributions, and budgets

- **No retraining**: use 30 P3-B learned residual heads in `p3b_checkpoints`, five seeds `48101–48105`, six model labels `clean/mixed × raw/log_phase/rms_log`. Compare against each associated, immutable P3-A2 `D_no_pos_10` backbone from seeds `47101–47105`. Verify SHA256 of checkpoints and metadata before evaluation. All models are evaluated in `eval` mode; no test-data-based calibration.
- New held-out pseudo-random stream `p3c` disjoint from P3-B training/evaluation. Test profiles `train3`, `equal4`, `long6`, `sparse12`; SNR `0,10,20 dB`; conditions `clean`, `pa_strong`, `impulse_strong`, `adc_strong` with P3-B code/settings unchanged. No deliberately adversarial emitters. For each P3-B seed × scenario: 256 frames (2 batches of 128), 30 unknown data symbols ×2 = 60 bits/frame. Thus 76,800 bits per method/profile/SNR/condition over five independently trained seeds. Identical frames across models/precision branches.
- **Primary operation-precision arms:** `fp32`, `autocast_fp16_realconv`, `autocast_bf16_realconv`. Input IQ and noise are kept FP32/complex64; both frozen backbone and the residual head execute inside the specified autocast context. Conv output dtypes must be audited via hooks, FFT dtypes remain complex64. Any unsupported kernel or runtime exception must be recorded, not silently substituted by FP32.
- **Separately isolated input-storage arms:** at 10 dB only, the same four channel profiles under `clean` and `adc_strong`; rounded `Ypilot`, `Ydata` complex components to FP16 then restored to FP32, or analogously BF16. Model and FFT computations remain FP32. Keep noise variance FP32; record whether input contains any Inf/NaN. The same quantized samples are offered to the three selected classical comparators (`threshold_no_align`, `dft8` and `train_lmmse`) as well as neural models. These arms must NOT be mislabeled as full half-precision inference.
- **Combined numerical arms:** on the same 10-dB/input-storage scenarios, use each stored-quantized input together with matching native lower-precision real-Conv1d autocast. These are mixed execution, not full low-precision FFT.
- **Coherent-gain stress:** separate test on equal4/10dB/clean with scales `2^-12`, `1`, and `2^12` applied to BOTH observed IQ streams and the corresponding reported noise power multiplied by scale squared; 256 frames per seed. Evaluate reference FP32 and the two combined quantized-plus-autocast branches. These are *artificial numerical gain changes*, not claims about physical ADC behavior or improvements in receiver sensitivity.
- **Algebraic representation stress:** deterministic log-spaced synthetic complex samples covering magnitudes 1e-8 through 1e8, plus exact zeros and near-axis cases. Record number of finite reconstructions and relative errors for raw Cartesian, log1p magnitude/regularized phase, and per-frame RMS-normalized Cartesian+logRMS storage under FP16 and BF16. Compare to exact FP64 source and explicitly distinguish software-quantized storage from ADC output and from learned model output.

## Metrics, inference, fairness

- For each trained seed and scenario, log integer bit errors/total evaluated bits for each network and precision branch; loss of a finite logit is an **explicit failure**, with nonfinite counts and no invented replacement BER. Log fraction of changed hard decisions and mean/max absolute logit deviation vs FP32, keeping run-level paired frames. Track backbone channel maximum absolute difference and Conv1d dtypes. The unit for training-repeat variation is five seeds, NOT individual bits.
- Classical reference methods under input quantization receive precisely the same rounded IQ and noise metadata. Do not select a different comparator per precision to manufacture a win. Report raw- and log-encoded neural heads across both `clean` and `mixed` training regimes.
- Measure CPU forward-time median and p95 with 20 warmups, 100 repetitions, batch1 and batch64, including full frozen-backbone+head path, separated by precision; no performance claims about power/energy, SDR, GPU or end-to-end RF latency.
- Primary **descriptive** cells: equal4/10dB/clean and sparse12/10dB/adc_strong; all other data also reported. No statistical significance-based model selection, no precision-mode tuning after results. If low-precision result is unusable, report it as a negative result.

## Independence / integrity

- Before evaluation: test FFT Half/BFloat16 unsupported and native Conv1d autocast returns respective lower dtype; verify frozen checkpoint loader; test input quantizer rounding and Inf detection, reported noise unchanged, no access to real `h`/unknown bits in model inference, and deterministic paired data streams.
- After: verify exact checkpoint hashes, recompute at least one independently specified held-out scenario per seed from disk without modifying models, check raw-vs-summary integer aggregation and derived metrics, check 5-seed coverage. No reusing historical held-out P3-B draws for P3-C; tests and stress use separate PRNG streams.
