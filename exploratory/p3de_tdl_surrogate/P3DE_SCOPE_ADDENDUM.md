# P3-D / P3-E scope: standards-bridge execution vs uncompleted formal work

**Date:** 2026-11-15. **Status:** *independent static 3GPP TDL-table surrogate completed; original Sionna 2.2-backed P3-D and its P3-E confirmation incomplete.*

The original P3-D plan explicitly required an execution of NVIDIA **Sionna 2.2** with standardized, dynamic 3GPP TR 38.901 TDL/CDL channels, its channel estimation API, and whole-link cost. The runtime has PyTorch 2.10 on CPU but **no Sionna**; `pip install sionna-no-rt==2.2.0` failed due DNS/network failure. We do not represent any standalone reproduction of its parameter tables as running Sionna.

To make progress without inventing a successful dependency install, a separate protocol was committed *before* training. We implemented a minimal static SISO fractional-delay OFDM surrogate using TDL-A/C/D tap delay and power arrays from Sionna v2.2.0, froze the two candidate models and fixed classical baselines, trained 10 fresh seed pairs, evaluated >1.3M bits per scenario/method at 0/10/20 dB, and audited original integer errors/weights. The resulting p-values and effects are only about **these standalone surrogate endpoints**, not about 3GPP compliance or Sionna performance.

**Remaining untested formal requirements:** actual Sionna code execution; Sionna TDL temporal evolution and Doppler; CDL, multi-antenna, and standardized numerology; resource grid and sparse pilots; Sionna-native LMMSE estimator; 16-QAM coded BLER; complete wall-clock receiver path on matched CPU/GPU; true independent software or hardware replication. Therefore the original P3-E confirmatory goal cannot be marked finished by these data. Proper formal evaluation requires Sionna to be available, an implementation parity test, and separately frozen held-out new seeds.

The simulation performs no intentional interference, real transmissions, antenna control, radar, weapon use or military target identification. Frozen historical P2-E, P3-A, P3-A2, P3-B and P3-C records are not modified. The public research outcome is narrow and mixed: both 985-parameter candidates improve over a **fixed classical hard-threshold** baseline in some table-driven scenarios, but the **training-information LMMSE** remains at least as good on both primary 10dB held-out profiles. Complex-channel MSE is much worse for the neural receiver despite QPSK BER, and the CPU forward call is slower. No general neural superiority or real-world receiver readiness is claimed.
